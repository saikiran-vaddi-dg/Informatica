Left excluded on purpose, not for complexity reasons.

Deploying it via `update_data_flow` failed output-schema resolution with `ORA-00942: table or view does not exist` against the live `W_GTAS_ACTIVITY_BALANCES_FS` JDBC connection (Oracle, schema `sh`) — isolated to confirm even `W_PARAM_G` alone (the simplest addition) fails identically, so the other 4 new tables are unlikely to be reachable either. This connection's schema owner (`sh`) looks like Oracle's generic sample schema rather than a populated GTAS instance. Live dataflow was reverted to the last working query so it isn't left broken. **Needs DBA/environment verification that these 5 tables are registered and reachable via this data source** before the draft can be redeployed — see the `_notes` array in the HRD file for full detail and the baked-in assumptions (AID hardcoded to `'075'`, ATA/SUB_ACCOUNT default to `'X'`) that also need re-verification once the tables are reachable.
